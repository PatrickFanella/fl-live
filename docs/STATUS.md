The first D1 engine slice is implemented. D0/D1 as a whole remain partial. D2–D5 are not complete. A generated WAV is not a usable workstation.

The Qt UI now uses the same controller; transport state comes from rendering acknowledgements. Template save/reload and stopped settings editing now work. Active-clip feedback now follows coherent render snapshots. Editing history now works while stopped. QML control signals now drive an edited MIDI pattern into independently captured PipeWire audio, including stopped silence. Next qualify native input and physical playback; imported media and free note positioning remain open. Preserve the private software-graph checks while qualifying physical devices, rate/quantum changes and extended workloads separately. See [backend contract](pipewire-backend.md) and [validation](../validation/pipewire-foundation.json).

The product repository is hosted privately at https://git.subcult.tv/subculture-collective/fl-live while licensing is undecided. The validated engine foundation is the initial main-branch baseline. A Gitea Actions workflow now covers desktop/release/engine-only/PipeWire sanitizer builds; its hosted result is tracked on the PR. Release qualification remains pending. The reference research archive was not moved into this repository. Its preservation requirements still govern native Soyuz experiments, not this local engine build.

The desktop now resolves its authored clips by stable IDs through prepared plans. Track/clip renaming is undoable and persists in the v3 authored wrapper; v1/v2 imports and source audio remain supported. The authored scene now has undoable naming and slot inclusion, persisted empty slots, atomic launch/stop and Immediate/One bar timing; generic four-track scene scheduling is checked offline. Scene creation, arrangement copy, ordering and deletion now support Undo/Redo and persistence; selection remains a view action. Track/clip management, independent clip duplication and the general musical Session remain open. See [scene controls](scene-controls.md) and [desktop identity integration](desktop-identities.md).
